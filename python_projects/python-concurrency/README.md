# 🐍 Параллельность в Python: процессы и корутины

### 📌 Обзор проекта

Две независимые программы на одну тему — как выполнять работу одновременно и чем
за это платить.

В первой параллельность **настоящая**: моделируется экзамен, где каждый экзаменатор
принимает в собственном процессе, а студенты стоят в одной общей очереди. Процессы
не делят память, поэтому вся сложность — в разделяемом состоянии: очередь, статусы,
статистика и таблица на экране должны сходиться между собой в любой момент.

Во второй параллельности нет вовсе: один поток и цикл событий `asyncio` качают
изображения, пока пользователь набирает следующую ссылку. Сложность зеркальная —
не заблокировать единственный поток.

Задача сформулирована как учебная, но обе ловушки в ней настоящие. В многопроцессной
части две ошибки из трёх ломают программу **молча**: правка вложенной структуры внутри
`Manager` просто не доходит до других процессов. В асинхронной — одна строка отделяет
работающую программу от той, которая формально асинхронна, а фактически
последовательна.

### 🏗 Архитектура

Программа 1. Пишут только процессы экзаменаторов и только под замком; главный процесс
ничего не считает, он читает снимок и рисует.

```
                       главный процесс
                  +----------------------------+
                  |  каждые 0.25 с:            |
                  |    snapshot() под Lock     |
                  |    clear + печать таблиц   |
                  +-------------+--------------+
                                | только чтение
                                v
        +========================================================+
        |             Manager: разделяемое состояние             |
        |   queue[]   current[]   status{}   finished_at{}       |
        |   duration{}   examiners{}   hits{}        + Lock      |
        +========================================================+
              ^                    ^                    ^
              | запись под Lock    |                    |
     +--------+-------+   +--------+-------+   +--------+-------+
     | Process Степан |   | Process Дарья  |   | Process Михаил |
     +----------------+   +----------------+   +----------------+
```

Программа 2. Ожидание клавиатуры уезжает в поток, цикл событий остаётся свободным.

```
   поток ввода (asyncio.to_thread)          цикл событий asyncio
   +-----------------------------+          +------------------------+
   | input("Ссылка: ")           |  create  |  download(url1) ...    |
   |   |                         | -------> |  download(url2) ...    |
   |   v                         |   task   |  download(url3) ...    |
   | пустая строка -> стоп       |          +-----------+------------+
   +--------------+--------------+                      |
                  |                                     |
                  +--------> gather(все задачи) <-------+
                                     |
                                     v
                          таблица «Ссылка / Статус»
```

Три модуля первой программы разделены **по парадигмам** — этого требует условие,
и граница совпала с границей ответственности:

| Файл | Парадигма | За что отвечает |
|---|---|---|
| `models.py` | объектная | правила задачи. Ни ввода-вывода, ни процессов |
| `report.py` | функциональная | чистые функции над снимком: таблицы и итоги |
| `main.py` | процедурная | файлы, процессы, цикл перерисовки |

Деление окупилось на проверке: `models.py` и `report.py` не зависят ни от процессов,
ни от ввода-вывода, поэтому вероятностные правила замеряются напрямую, без запуска
всей машинерии.

### 🚀 Что интересного

* **Разделяемый словарь не замечает правку вложенной структуры.** Состояние
  экзаменатора хранится кортежем и переприсваивается целиком. Если хранить список
  и написать `state['Степан'][1] += 1`, изменится локальная копия в своём процессе,
  до менеджера она не дойдёт, и ошибки не будет — только разъедутся числа в таблице.

* **Генератор не проходит через `Manager`.** Аргументы `manager.list(...)` пиклятся
  и уходят в процесс менеджера, а генераторное выражение не пиклится. Отсюда
  квадратные скобки в `manager.list([...])`: иначе `TypeError: cannot pickle
  'generator' object`.

* **Один `input()` решает, асинхронная программа или нет.** Обычный вызов заблокировал
  бы цикл событий, и следующую ссылку спросили бы только после загрузки предыдущей.
  `asyncio.to_thread` уводит ожидание в поток. На прогоне это видно числом: к моменту
  конца ввода четыре загрузки из пяти ещё шли.

* **Веса золотого сечения считаются остатком, а не формулой.** Условие задаёт их
  рекуррентно (`a = 1/Ф`, `b = (1-a)/Ф`, …). Цикл, где каждый следующий вес — остаток,
  делённый на Ф, а последнее слово забирает всё оставшееся, воспроизводит эти формулы
  и заодно гарантирует сумму ровно `1.0` при любом числе слов.

* **Поведение, похожее на баг, требуется условием.** Студент, которого прямо сейчас
  опрашивают, показан со статусом «Очередь» и учтён в счётчике оставшихся — так
  устроен пример в задании. Статус меняется в момент вердикта, а не в момент захода
  к экзаменатору.

* **Пример в условии сам себе противоречит.** У экзаменатора с именем из шести букв
  показаны два студента и 7.21 с работы, хотя шесть букв дают минимум 5 секунд
  на одного. Выбрано толкование, при котором сходятся остальные столбцы: «Время
  работы» — это время, реально потраченное на приём, оно замирает на обеде и после
  окончания.

* **Порог «более 85%» на семи студентах жёстче, чем выглядит.** `6/7 = 85.7%`
  проходит, `5/7` уже нет: удачным экзамен считается, только если провалился не более
  одного студента. Обе ветки вывода получены живьём.

### 📂 Что в папке

| Путь | Назначение |
|---|---|
| `exercise0/models.py` | правила задачи: вопрос, студент, экзаменатор, золотое сечение |
| `exercise0/report.py` | чистые функции: таблицы и итоговые строки |
| `exercise0/main.py` | разделяемое состояние, процессы, цикл перерисовки |
| `exercise0/*.txt` | входные данные: экзаменаторы, студенты, банк вопросов |
| `exercise1/main.py` | асинхронное скачивание изображений |
| `run.sh` | запуск обеих программ и проверка синтаксиса; поднимает `.venv` |
| `main_report.md` | подробный разбор с фактическим выводом обеих программ |

Условия заданий не публикуются, их формулировки пересказаны в отчёте своими словами.

### ▶️ Запуск

```bash
./run.sh          # меню
./run.sh exam     # программа 1 — экзамен на процессах
./run.sh images   # программа 2 — асинхронное скачивание
./run.sh check    # py_compile всех модулей + bash -n
```

Первый запуск создаёт `.venv` рядом с проектом и ставит туда `aiohttp`
и `prettytable`. Отдельный шаг нужен потому, что системный Python защищён PEP 668
и `pip install` в него падает с `externally-managed-environment`.

Экзамен на семи студентах из комплекта занимает около 14 секунд. **Обед при этом
не наступает**: перерыв полагается через 30 секунд после начала, а экзамен
заканчивается раньше. Чтобы увидеть перерыв, нужен список подлиннее — на 24 студентах
он срабатывает у каждого экзаменатора ровно один раз.

Скачивание можно проверить без внешней сети, локальным сервером:

```bash
python3 -m http.server 8731        # в каталоге с картинками
./run.sh images                    # ссылки вида http://127.0.0.1:8731/имя.jpg
```

### 📈 Итоговый результат

Обе программы отрабатывают, `./run.sh check` проходит, `shellcheck` по `run.sh`
молчит. Весь вывод в отчёте — фактический, снят с прогонов и не правился.

Правила задачи проверены не только глазами. Веса золотого сечения дают сумму ровно
`1.0000000000` и совпадают с формулами условия до последнего разряда; распределение
ответов на 100 000 прогонов сошлось с ожидаемым (0.618 / 0.236 / 0.146 и зеркально
для другого пола); вероятности настроения на 200 000 прогонов дали 0.250 при слабых
ответах и 0.877 при сильных — то есть `1/4` и `1 − 1/8`, как в условии. На 234 живых
кадрах порядок таблицы студентов ни разу не нарушился, а счётчик оставшихся ни разу
не разошёлся с содержимым таблицы.

Скачивание проверено на пяти ссылках сразу, включая заведомо битые: три успеха, HTTP 404
и несуществующий домен. Программа не упала ни на одном отказе, совпадение имён файлов
разрешилось суффиксом, а каталог без прав на запись был отклонён с повторным запросом
пути.
