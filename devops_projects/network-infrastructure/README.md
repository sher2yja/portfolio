# 🌐 Сети в Linux: маршрутизация, фильтрация, NAT

### 📌 Обзор проекта

Стенд из пяти виртуальных машин: две подсети, разделённые двумя маршрутизаторами. Настраивается всё, что нужно, чтобы трафик ходил между сетями и при этом контролировался — статическая маршрутизация, сетевой экран, автоматическая раздача адресов, трансляция адресов и SSH-туннели.

Проект отвечает на вопрос, который в остальной инфраструктуре обычно скрыт: **как пакет попадает из одной сети в другую**. Дальше это знание работает в фоне — при настройке overlay-сетей Docker, публикации сервисов через Ingress и разборе проблем со связностью в кластере.

        │         │                        │        │    │10.20.0.20│
   ┌────┴─────────┴──┐                ┌────┴────────┴──┐ └──────────┘
   │       r1        │                │       r2       │             
   │ enp0s3 10.10.0.1│◄──────────────►│enp0s3 10.100.0.12
   │ enp0s8 10.100.0.11               │enp0s8 10.20.0.1│

Рабочие станции знают только свой шлюз. Маршрутизаторы знают друг о друге и о чужой подсети — этого достаточно для связи в обе стороны.

### 🚀 Ключевые этапы реализации

* **Расчёт адресного пространства.** Работа с `ipcalc`: перевод масок между префиксной, десятичной и двоичной записью, определение диапазонов хостов, разбор частных и публичных адресов. Три адреса из проверочного списка выглядят частными, но ими не являются — близость первого октета ничего не решает.

* **Маршрут, который переживает перезагрузку.** `ip route add` правит таблицу маршрутизации ядра и живёт до первого рестарта. Постоянный маршрут прописывается в Netplan — разница принципиальна для любой настройки, которую делают не на один раз.

* **Форвардинг включается отдельно.** Машина с двумя интерфейсами маршрутизатором сама по себе не становится: Linux по умолчанию не пересылает пакеты между интерфейсами. Нужен `net.ipv4.ip_forward=1`, и в `/etc/sysctl.conf`, а не только через `sysctl -w`.

* **Правило самого длинного префикса.** Из всех подходящих маршрутов выбирается тот, у которого с адресом назначения совпадает больше бит. Маршрут по умолчанию `0.0.0.0/0` не фиксирует ни одного бита и потому работает как запасной вариант, а не как основной.

* **Порядок правил iptables решает исход.** Два варианта `firewall.sh` отличаются только тем, какое из двух правил — `DROP` или `ACCEPT` — стоит выше. Результат прямо противоположный: правила проверяются сверху вниз, применяется первое совпавшее, до остальных дело не доходит.

* **Отсутствие ответа на ping ≠ машина недоступна.** После блокировки ICMP машина перестаёт отвечать на пинг, но `nmap` видит её активной и находит открытые порты. Полезное различение при диагностике.

* **NAT в обе стороны.** SNAT маскирует адреса частной сети за адресом маршрутизатора при выходе наружу. DNAT решает обратную задачу: порт 8080 на маршрутизаторе перенаправляется на порт 80 машины, у которой собственного внешнего адреса нет.

* **SSH-туннели к закрытому сервису.** Apache намеренно перенастроен на `Listen localhost:80` и снаружи недоступен. Local forwarding открывает к нему доступ с той машины, которой он нужен; remote forwarding — наоборот, с той, где сервис работает.

### 📈 Итоговый результат

Стенд работает: трафик ходит между подсетями через два маршрутизатора, фильтруется по заданным правилам, адреса раздаются автоматически с привязкой по MAC, машины частной сети выходят наружу через SNAT, а снаружи доступны через DNAT. Закрытый на localhost сервис открывается туннелем в обе стороны.

Главная польза проекта — набор инструментов диагностики, к которым обращаются, когда «сеть не работает»: `ip r` показывает, куда пойдёт пакет, `traceroute` — через какие узлы, `tcpdump` — что реально ушло с интерфейса, `nmap` — жив ли узел, если он молчит на ping.
