# Персистентность Redis

Redis работает отдельным StatefulSet с PVC на 1 ГиБ, чтобы данные очереди не исчезали только из-за пересоздания Pod. Это снижает риск, но не доказывает гарантированного повторного выполнения: при принудительной потере worker один опыт закончился ошибкой задания. В отдельном тестовом namespace Redis остановили при десяти активных 30-секундных задачах. После возврата сервиса новые задачи снова завершались, но пять прежних execution получили статус `crashed`, а пять остались `running` спустя две минуты. Поэтому PVC не заменяет политику повторов, идемпотентность workflow и разбор незавершённых execution после аварии.
