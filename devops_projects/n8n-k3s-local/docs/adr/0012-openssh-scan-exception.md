# Узкое исключение для CVE-2026-60002 в базовом образе n8n

Дата: 25.09.2026. Статус: временно принято владельцем проекта.

## Контекст

Trivy обнаружил семь записей CRITICAL в образе на основе `n8nio/n8n:2.40.7`: это один `CVE-2026-60002`, повторённый для семи пакетов OpenSSH `10.3_p1-r0`. Alpine указывает исправление `10.3_p1-r1`. Уязвимость относится к SSH-клиенту при смене ключа сервера во время повторного согласования; она не относится к HTTP-интерфейсу n8n или `sshd` как серверу. Сценарии DO14 не запускают SSH-клиент внутри n8n.

В официальном финальном образе нет `apk`. Попытки вернуть его по [инструкции n8n](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.executecommand/) и затем обновить или удалить OpenSSH не прошли: пакетная база базового образа фиксирует другие системные пакеты контрольными суммами, и решатель отклонил изменения. Подменять эту базу или отключать сканирование целиком нельзя.

## Решение

Производный Dockerfile удаляет `/usr/bin/ssh`, `/usr/bin/scp` и `/usr/bin/sftp`. Стадия build проверяет запуск n8n и отсутствие этих команд. Полный отчёт Trivy сохраняется; gate не считает блокирующими только записи CRITICAL с точным ID `CVE-2026-60002` и именем пакета, начинающимся с `openssh`. Все прочие CRITICAL по-прежнему останавливают `test` и деплой. Исключение не означает, что пакетная база или исходный образ исправлены.

## Риск и пересмотр

Остаются метаданные и другие компоненты OpenSSH в образе. Если появится сценарий, которому нужен SSH-клиент, исключение недействительно: перед включением такого сценария нужен исправленный образ. При следующем обновлении n8n проверить отчёт Trivy; как только официальный образ получит исправленный OpenSSH, удалить исключение и вернуть обычный gate без изменения порога. Не позднее следующего релиза n8n пересмотреть это решение вручную.

Источники: [описание CVE в GitHub Advisory Database](https://github.com/advisories/GHSA-gp5v-jg37-fvg6), [документация n8n об отсутствии `apk`](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.executecommand/).
