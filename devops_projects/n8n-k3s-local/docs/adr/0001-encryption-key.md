# Общий ключ шифрования для ролей n8n

Все роли n8n внутри одного окружения получают `N8N_ENCRYPTION_KEY` из одного существующего Kubernetes Secret. Staging и production используют разные Secret и ключи. Генерация ключа при каждом Helm-деплое или отдельный ключ на worker сделали бы сохранённые credentials недоступными; поэтому дамп PostgreSQL восстанавливается только вместе с исходным ключом. Secret создаётся оператором вне чарта и не попадает в Git.

Проверено отказным опытом в изолированном `do14-restore-credential`: временная копия чарта генерировала новый `N8N_ENCRYPTION_KEY` через `randAlphaNum` в Secret при upgrade. Пароль PostgreSQL и токен runner оставались прежними, версия n8n не менялась. С новым ключом main завершал запуск с ошибкой `Deployment key 'signing.hmac' cannot be read with this instance encryption key`; worker и webhook также не достигли устойчивой готовности. `helm upgrade --atomic --wait` не прошёл и автоматически откатился. Повторный короткий upgrade подтвердил сообщение в журнале, затем ручной `helm rollback` восстановил штатный Secret: workflow с сохранённым PostgreSQL credential снова вернул HTTP 200 и `{"credential_ok":1}`. Временный Secret исчез после отката, тестовый namespace масштабирован до нуля. Ошибочный шаблон удалён и никогда не применялся в staging или production.
