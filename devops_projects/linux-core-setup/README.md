# 🐧 Установка и администрирование Ubuntu Server

### 📌 Обзор проекта

Первый проект траектории: развёртывание серверной Ubuntu с нуля и приведение её в рабочее состояние — сеть, права доступа, удалённый доступ, диагностика. Всё выполняется в консоли, без графического окружения.

Отсюда растёт вся дальнейшая инфраструктура: схема стенда на виртуальных машинах и навыки работы в терминале используются во всех последующих проектах — от настройки сетей до развёртывания кластеров Kubernetes.

### 🚀 Ключевые этапы реализации

* **Установка и учётные записи:** развёртывание Ubuntu Server 20.04 LTS в минимальной конфигурации, создание непривилегированного пользователя, проверка записи в `/etc/passwd`.

* **Сетевая конфигурация:** переход с DHCP на статическую адресацию через Netplan — статический IP, маршруты, DNS. Применение через `netplan try`, который откатывает конфигурацию сам, если подтверждение не получено: страховка от потери доступа к удалённой машине.

* **Разграничение прав:** настройка `sudo` для выполнения привилегированных команд без постоянной работы под root — права выдаются на команду, а не на сессию, и каждое обращение фиксируется в журнале.

* **Защита удалённого доступа:** установка `openssh-server` с автозапуском, перенос службы со стандартного 22 порта на 2022, проверка процесса и прослушиваемого сокета через `ps` и `netstat`.

* **Диагностика системы:** `top` и `htop` для анализа нагрузки, `fdisk` для просмотра разметки дисков, `df`, `du` и `ncdu` для контроля дискового пространства, разбор журналов авторизации.

* **Автоматизация:** задача в CRON, записывающая состояние системы в журнал по расписанию, с последующей проверкой результата и удалением задачи.

### 📂 Что в папке

| Путь | Назначение |
|---|---|
| `main_report.md` | отчёт: 15 разделов с командами и результатами |
| `images/` | 50 скриншотов работы со стендом |

Конфигурационных файлов в репозитории нет: задача решается настройкой уже установленной системы, а не написанием кода. Результат каждого шага зафиксирован скриншотом в отчёте.

### 📈 Итоговый результат

Собран рабочий сервер с предсказуемой сетевой конфигурацией и защищённым удалённым доступом. Освоен набор инструментов диагностики, к которому обращаются при разборе проблем на любом Linux-сервере.

Главное, что даёт проект дальше, — понимание того, что происходит внутри виртуальной машины до того, как на неё придут Docker, Kubernetes и системы мониторинга.
