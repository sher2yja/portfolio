# Bash: сбор сведений о системе и статистика файловой системы

Отчёт о выполнении проекта: пять скриптов на Bash — от разбора аргументов командной строки до обхода файловой системы с построением рейтингов.

Задание сдавалось без скриншотов, поэтому в отчёте приведён **реальный вывод скриптов**, полученный повторным прогоном. Прогон сделан на другой машине, чем при сдаче (Ubuntu 24.04 против 20.04), — это дало дополнительный результат, описанный в разделе про часть 2.

---

## Часть 1. Разбор входного параметра

Скрипт принимает ровно один текстовый аргумент и отвергает всё остальное. Проверка «аргумент не является числом» вынесена в отдельный файл [util.sh](./01/util.sh), который обменивается с основным скриптом **кодом возврата**, а не выводом:

```bash
is_number() {
  local re='^[0-9]+$'
  if [[ $1 =~ $re ]]; then
    return 0
  else
    return 1
  fi
}
```

Такой обмен позволяет поставить вызов прямо в условие, без разбора текста:

```bash
if ./util.sh "$param"; then
  echo "Параметр не может быть числом"
  exit 1
```

### Прогон

```
$ ./main.sh
Необходимо ввести один текстовый параметр      (код возврата 1)

$ ./main.sh a b
Необходимо ввести один текстовый параметр      (код возврата 1)

$ ./main.sh 42
Параметр не может быть числом                  (код возврата 1)

$ ./main.sh ""
Параметр не может быть пустым                  (код возврата 1)

$ ./main.sh hello
Параметр: hello                                (код возврата 0)
```

Вспомогательный скрипт ищется рядом с основным, а не в текущем каталоге:

```bash
if "$(dirname "$0")/util.sh" "$param"; then
```

Иначе запуск вида `bash 01/main.sh hello` из родительской папки не нашёл бы `util.sh`. В части 5 та же задача решена так же.

## Часть 2. Сведения о системе

Скрипт собирает пятнадцать параметров машины штатными утилитами: `hostname`, `timedatectl`, `/etc/os-release`, `uptime`, `/proc/uptime`, `ip`, `free`, `df`.

Данные сначала складываются в одну переменную и только потом выводятся:

```bash
OUTPUT="HOSTNAME = $HOSTNAME
TIMEZONE = $TIMEZONE UTC $UTC_OFFSET
...
SPACE_ROOT_FREE = $SPACE_ROOT_FREE"

echo "$OUTPUT"
```

Так один и тот же текст попадает и на экран, и в файл — без повторного сбора и без риска, что сохранённая копия разойдётся с показанной.

### Маска подсети

`ip` выдаёт префикс (`/8`), а по условию нужна полная форма (`255.0.0.0`). Перевод делает `ipcalc`, если он установлен, иначе срабатывает таблица соответствий на 33 значения.

### Сохранение в файл

По ответу `Y` вывод пишется в файл, имя которого собирается из отметки времени, — повторные запуски не затирают друг друга:

```bash
TIMESTAMP=$(date +"%d_%m_%y_%H_%M_%S")
FILENAME="${TIMESTAMP}.status"
```

Результат сдаточного прогона сохранён в репозитории — [23_07_25_19_05_39.status](./02/23_07_25_19_05_39.status):


### Что показал повторный прогон на другой машине

При запуске на Ubuntu 24.04 без установленного `ipcalc` поле `MASK` осталось пустым, хотя резервная таблица для этого случая была написана.

Причина оказалась в способе определения:

```bash
if ipcalc 2>&1 | grep -q "Command 'ipcalc' not found"; then
```

Строку `Command 'ipcalc' not found` печатает не сам shell, а обработчик `command-not-found`, который подключается только в интерактивном сеансе. Внутри скрипта bash выводит другое сообщение — `ipcalc: command not found`, — оно под шаблон не подходит, признак остаётся положительным, и скрипт всё равно идёт в ветку с `ipcalc`. Резервная таблица не срабатывала никогда.

Проверка заменена на `command -v`, которая смотрит наличие команды напрямую и от текста сообщений не зависит:

```bash
if command -v ipcalc >/dev/null 2>&1; then
    IPCALC_INSTALLED=true
else
    IPCALC_INSTALLED=false
fi
```

На машине сдачи `ipcalc` присутствовал, поэтому расхождение там не проявлялось. Именно в этом и была ценность прогона на другой системе.

## Часть 3. Цветной вывод, цвета из аргументов

Работа с цветом вынесена в модуль [colors.sh](./03/colors.sh), который подключается через `source` и предназначен только для этого. Прямой запуск он отклоняет:

```bash
if [[ "${BASH_SOURCE[0]}" == "${0}" ]]; then
    echo "Файл должен быть подключен через source, а не запущен напрямую."
    exit 1
fi
```

Сравнение работает потому, что при подключении через `source` переменные расходятся: `BASH_SOURCE[0]` указывает на сам модуль, а `$0` — на вызывающий скрипт.

Цвета задаются числами от 1 до 6, а не ANSI-кодами: проверка ввода сводится к сравнению чисел, а от пользователя не требуется знать про escape-последовательности. Перевод в коды делает `case` внутри модуля.

### Прогон

```
$ ./main.sh
Введите 4 параметра цифрами от 1 до 4:
1.фон названий
2.цвет шрифта
3.фон значений
4.цвет шрифта значений

$ ./main.sh 2 2 3 1
Ошибка: Цвета и фоны не могут совпадать.

$ ./colors.sh
Файл должен быть подключен через source, а не запущен напрямую.
```

Корректный вызов `./main.sh 6 1 2 4` выводит те же пятнадцать параметров, что и часть 2, но парами с раскраской. В виде управляющих последовательностей это выглядит так:

```
^[[40;97mHOSTNAME = ^[[0m^[[41;94mdevops-Nitro-AN517-52^[[0m
^[[40;97mTIMEZONE = ^[[0m^[[41;94mEurope/Amsterdam UTC +2^[[0m
^[[40;97mUSER = ^[[0m^[[41;94mdevops^[[0m
```

Каждое значение закрывается сбросом `\e[0m` — без него окраска утекла бы на последующий вывод терминала.

## Часть 4. Цветной вывод, цвета из конфигурационного файла

Развитие предыдущей части: цвета переезжают из аргументов в [config.conf](./04/config.conf), а у каждого параметра появляется значение по умолчанию.

### Разбор конфига без source

Конфигурационный файл читается построчно, а не подключается как код:

```bash
while IFS='=' read -r key value || [ -n "$key" ]; do
    [ -z "$key" ] && continue
    [[ "$key" =~ ^[[:space:]]*# ]] && continue

    key=$(echo "$key" | sed 's/^[[:space:]]*//; s/[[:space:]]*$//')
    value=$(echo "$value" | sed 's/^[[:space:]]*//; s/[[:space:]]*$//; ...')

    case "$key" in
        column1_background) column1_background="$value" ;;
        ...
    esac
done < "$CONFIG_FILE"
```

Подключить конфиг через `source` было бы короче, но тогда любая строка в файле выполнилась бы как команда с правами скрипта. Разбор с явным списком допустимых ключей в `case` этого не позволяет: всё, что не перечислено, игнорируется.

Условие `|| [ -n "$key" ]` обрабатывает последнюю строку файла, если она не завершается переводом строки, — иначе `read` вернул бы её и сразу отчитался о конце файла, и параметр потерялся бы.

Значения по умолчанию подставляются штатной подстановкой bash:

```bash
column1_background=${column1_background:-$DEFAULT_COLUMN1_BACKGROUND}
```

### Прогон

С конфигом:

```
$ ./main.sh
...
Column 1 background = 2 (red)
Column 1 font color = 4 (blue)
Column 2 background = 5 (purple)
Column 2 font color = 1 (white)
```

Без файла конфигурации:

```
$ mv config.conf config.bak && ./main.sh
...
Column 1 background = default (black)
Column 1 font color = default (white)
Column 2 background = default (red)
Column 2 font color = default (blue)
```

С конфликтом цвета и фона в конфиге:

```
$ ./main.sh
Ошибка: Цвета и фоны не могут совпадать.
```

Пометка `default` показывает, какие значения пользователь не переопределял, — по выводу видно не только результат, но и то, откуда он взялся.

### Маска без внешних утилит

В этой части `ipcalc` вызывался напрямую, без проверки и без запасного пути, — на системе без него поле `MASK` выходило пустым. Дублировать таблицу на 33 значения третий раз смысла нет, поэтому маска считается арифметикой:

```bash
cidr_to_mask() {
    local bits=$(( 0xffffffff ^ ((1 << (32 - $1)) - 1) ))
    printf "%d.%d.%d.%d" $(( bits >> 24 & 255 )) $(( bits >> 16 & 255 )) \
                         $(( bits >> 8 & 255 ))  $(( bits & 255 ))
}
```

Из 32 единиц гасятся младшие `32 − префикс` разрядов, затем число разбирается на октеты сдвигами. Результат сверен с таблицей из части 2 на всех значениях от `/0` до `/32` — расхождений нет.

## Часть 5. Статистика по каталогу

Задача разложена на три файла: [main.sh](./05/main.sh) разбирает аргумент и замеряет время, [count.sh](./05/count.sh) считает количества, [top.sh](./05/top.sh) строит рейтинги.

Вложенные скрипты вызываются относительно расположения главного, а не текущего каталога:

```bash
bash "$(dirname "$0")/count.sh" "$DIR_PATH"
```

Иначе запуск из другого каталога сломал бы их поиск.

Время замеряется с точностью до наносекунд, а вычитание отдаётся `bc` — bash не умеет вычитать дробные числа:

```bash
start_time=$(date +%s.%N)
...
elapsed_time=$(echo "$end_time - $start_time" | bc)
```

### Что считается и как

**Количества** — проходами `find` с разными фильтрами. Из числа каталогов вычитается единица: `find` включает в вывод сам каталог обхода.

Текстовые файлы определяются не по расширению, а по выводу `file` — расширение в Linux ничего не гарантирует. Это самая медленная проверка: `file` запускается на каждый файл.

**Рейтинги** сортируются через `sort -hr`. Ключ `-h` понимает суффиксы `K`, `M`, `G` в выводе `du`; обычная сортировка поставила бы `9K` выше `10M`.

В топе каталогов берутся строки со второй по шестую:

```bash
du -h "$DIR_PATH" | sort -hr | head -n 6 | tail -n 5
```

Первой строкой `du` печатает сам каталог обхода — он всегда крупнее вложенных и вытеснил бы из рейтинга реальный результат.

Обход файлов сделан через `-exec du -h {} +`, а не `\;`: плюс на конце заставляет `find` передавать файлы пачками, а не вызывать `du` на каждый. На каталогах с тысячами файлов разница во времени существенная.

## Итоги

Пять частей закрывают разные стороны работы с Bash: разбор аргументов и коды возврата, сбор системных сведений штатными утилитами, модульность через `source`, чтение конфигурации без исполнения её как кода, обход файловой системы с сортировкой и хешированием.

Отдельная сквозная линия — независимость от того, что может отсутствовать в системе. `ipcalc` не входит в базовую поставку Ubuntu, поэтому перевод префикса в маску нигде не полагается на него как на единственный вариант: в частях 2 и 3 работает таблица соответствий, в части 4 — расчёт сдвигами. То же и с конфигурационным файлом: он необязателен, при его отсутствии берётся схема по умолчанию.

В результате скрипты запускаются на любой системе с coreutils, без установки зависимостей и без подготовки окружения.
