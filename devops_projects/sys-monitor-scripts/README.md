# 🐚 Bash: сведения о системе и статистика файловой системы

### 📌 Обзор проекта

Пять скриптов на Bash, каждый решает свою задачу: разбор аргументов командной строки, сбор сведений о машине штатными утилитами, цветной вывод с настройкой из аргументов и из конфигурационного файла, обход файловой системы с построением рейтингов по размеру.

Проект про инструменты, которые уже есть в любой системе. Всё считается связкой `find`, `du`, `awk`, `sed`, `sort` и `file` — без установки чего-либо дополнительного.

### 🚀 Ключевые решения

* **Обмен через код возврата, а не через вывод.** Проверка «аргумент не число» вынесена в `util.sh`, который ничего не печатает и возвращает 0 или 1. Вызов встаёт прямо в условие `if`, без разбора текста.

* **Сбор данных отделён от вывода.** В части 2 все пятнадцать параметров сначала складываются в одну переменную и только потом печатаются. Благодаря этому на экран и в файл уходит один и тот же текст — сохранённая копия не может разойтись с показанной.

* **Модуль, который нельзя запустить.** `colors.sh` предназначен только для подключения через `source` и прямой запуск отклоняет: при подключении `${BASH_SOURCE[0]}` и `$0` расходятся, при запуске совпадают.

* **Конфиг читается, а не исполняется.** Подключить `config.conf` через `source` было бы на пять строк короче, но тогда любая строка в файле выполнилась бы как команда с правами скрипта. Вместо этого файл разбирается построчно, а список допустимых ключей задан явным `case` — всё лишнее игнорируется.

* **Значения по умолчанию и пометка `default`.** Скрипт работает и без конфигурационного файла, а в конце печатает использованную схему, отмечая словом `default` то, что пользователь не переопределял: по выводу видно не только результат, но и его источник.

* **Сортировка размеров, а не строк.** Рейтинги строятся через `sort -hr` — ключ `-h` понимает суффиксы `K`, `M`, `G` в выводе `du`. Обычная сортировка поставила бы `9K` выше `10M`.

* **Тип файла определяется по содержимому.** Текстовые файлы считаются по выводу `file`, а не по расширению: в Linux расширение ничего не гарантирует. Плата — время: на `/etc` скрипт работает около десяти секунд.

### 📈 Итоговый результат

Набор скриптов работает на любой системе с coreutils и не требует установки зависимостей. Каждая часть проверена на корректных и некорректных входных данных, вывод приведён в отчёте.

Скрипты сознательно не полагаются на то, чего может не оказаться в системе. `ipcalc` не входит в базовую поставку Ubuntu, поэтому перевод сетевого префикса в полную маску нигде не зависит от него как от единственного варианта: в частях 2 и 3 работает таблица соответствий, в части 4 — расчёт сдвигами. Конфигурационный файл в части 4 тоже необязателен — без него берётся схема по умолчанию. Разбор — в [отчёте](./main_report.md#что-показал-повторный-прогон-на-другой-машине).
