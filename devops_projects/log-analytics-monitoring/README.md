# 📊 Мониторинг в реальном времени: нагрузка, логи, метрики

### 📌 Обзор проекта

Проект соединяет две стороны наблюдаемости: **чем нагружать** и **чем смотреть**. Скрипты на Bash создают и убирают нагрузку на файловую систему, генерируют и разбирают логи nginx, а стенд из Prometheus и Grafana показывает, как машина на эту нагрузку реагирует.

Отдельная часть — собственный экспортёр метрик: Prometheus собирает данные из файла, который пишет обычный bash-скрипт, наравне со штатными источниками.

### 🏗 Как части связаны

```
   ┌── нагрузка ──────────────────────────────────────────┐
   │                                                       │
   │  01/  структура папок и файлов в заданном каталоге    │
   │  02/  заполнение диска: 100 папок или 1 ГБ ───┐       │
   │  03/  уборка: по журналу, по дате, по маске    │      │
   └────────────────────────────────────────────────┼──────┘
                                                    │
   ┌── логи ────────────────────────────────────────┼──────┐
   │                                                │      │
   │  04/  генерация логов nginx (формат COMBINED)  │      │
   │        │                                       │      │
   │        ├──► 05/  разбор через awk              │      │
   │        └──► 06/  HTML-отчёт через goaccess     │      │
   └────────────────────────────────────────────────┼──────┘
                                                    │
   ┌── наблюдение ──────────────────────────────────┼──────┐
   │                                                ▼      │
   │  07/  Prometheus + Grafana, свой дашборд ◄── нагрузка │
   │  08/  готовый дашборд Node Exporter,                  │
   │       нагрузка сети через iperf3                      │
   │  09/  собственный экспортёр метрик:                   │
   │       bash-скрипт → файл → nginx :8080 → Prometheus   │
   └───────────────────────────────────────────────────────┘
```

Части не независимы: часть 3 убирает за частью 2, части 5 и 6 разбирают логи части 4, а часть 7 наблюдает за машиной под нагрузкой, которую создаёт часть 2.

### 📂 Что в папке

| Часть | Файлы | Задача |
|---|---|---|
| `01/` | `main.sh`, `validation.sh` | структура папок и файлов, остановка по свободному месту |
| `02/` | 6 скриптов | заполнение файловой системы, ведение журнала |
| `03/` | 5 скриптов | три способа уборки созданного |
| `04/` | 3 скрипта | генерация логов nginx за 5 дней |
| `05/` | `main.sh` | разбор логов через `awk`, 4 режима |
| `06/` | `main.sh` | HTML-отчёт через `goaccess` |
| `09/` | `main.sh` | экспортёр метрик в формате Prometheus |

Плюс [main_report.md](./main_report.md) — отчёт по всем девяти частям и `images/` с 27 скриншотами стенда.

> **Часть 2 занимает место на диске намеренно** — это её задача, она служит источником нагрузки для части 7. Остановок две, срабатывает первая из наступивших: сто созданных папок либо остаток свободного места в 1 ГБ. В обычном прогоне первой наступает граница по числу папок — порядка 250 МБ при размере файла `1Mb`.
>
> По умолчанию работа идёт внутри песочницы `02/sandbox`, и всё созданное убирается одной командой. Поведение из задания — разбрасывание по всей файловой системе — включается явным параметром и требует подтверждения:
>
> ```bash
> ./main.sh az az.az 3Mb        # песочница
> ./main.sh az az.az 3Mb /      # по всей машине, с подтверждением
> ```

### 🚀 Ключевые решения

* **Генерация имён без счётчика коллизий.** Имя строится из индекса: остаток от деления задаёт, какую букву повторить, частное — сколько раз. Комбинации не пересекаются по построению, проверять уникальность не нужно.

* **Проверка свободного места перед каждым файлом.** Не раз за цикл по папкам, а на каждом шаге — иначе создание пачки файлов успело бы перешагнуть порог.

* **Локаль ломает арифметику.** `df -h` при русской локали отделяет дробную часть запятой, а `bc` такое число не принимает. Замена запятой на точку — единственное, что отделяет рабочую проверку порога от молчаливо неверной.

* **Три способа уборки и разная их надёжность.** Удаление по журналу точное: часть 2 при создании записывает каждый путь. Удаление по дате или маске работает по признаку и может зацепить постороннее — это ограничение самого подхода, а не реализации.

* **Уборка ограничена корнем, а не файловой системой.** Область работы часть 2 записывает первой строкой журнала, и все три способа очистки удаляют только внутри неё. Граница проверяется даже при удалении по журналу: журнал — обычный текстовый файл, который можно отредактировать. Удаление по дате и по маске дополнительно показывает найденное и ждёт подтверждения, а маска из одних звёздочек отклоняется.

* **Свой формат логов не понадобился.** Логи генерируются в COMBINED — том же, что пишет nginx. Благодаря этому их разбирает и `awk`, и `goaccess` без единой строки адаптации.

* **Загрузка процессора считается, а не читается.** Готовой метрики «занятость ЦП» нет: Prometheus отдаёт накопленное время в каждом режиме. `irate` превращает счётчик в скорость роста, вычитание доли простоя из ста даёт занятость.

* **Экспортёр метрик без единой строки HTTP.** Скрипт только пишет текстовый файл в формате экспозиции Prometheus, отдаёт его nginx на отдельном порту. Prometheus не различает, кто на другом конце, и собирает такие метрики наравне со штатными.

### 📈 Итоговый результат

Стенд работает целиком: нагрузка создаётся, наблюдается на дашбордах, убирается; логи генерируются, разбираются и сводятся в отчёт; собственные метрики доходят до Prometheus и доступны для запросов рядом с метриками `node_exporter`.

Наиболее содержательная часть — девятая. Она снимает представление об экспортёре как о сложной отдельной программе: достаточно писать текстовый файл в известном формате и отдавать его любым веб-сервером.
